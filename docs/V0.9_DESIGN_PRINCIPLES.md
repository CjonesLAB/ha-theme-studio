# Theme Studio 0.9 design principles

Version 0.9 rebuilds the editing workflow around two non-negotiable rules: mobile first and native Home Assistant behavior.

## 1. Mobile first

- Every workflow is designed and tested at phone width before tablet and desktop enhancements are added.
- Touch targets are at least 44 x 44 pixels; primary actions should be 48 pixels high where space allows.
- Core actions never require hover, a mouse, a hardware keyboard, or a desktop-only context menu.
- Settings and preview use a single-column flow on phones. Wider layouts may place them side by side without adding desktop-only functionality.
- Dialogs and panels must not cover the content a user needs to understand the current change.
- Reduced-motion preferences, safe areas, scrolling, focus order, and the Home Assistant Companion App are part of acceptance testing.

## 2. Home Assistant native only

- Theme Studio does not create or require custom dashboard cards.
- Theme Studio does not depend on card-mod, UIX, Mushroom, Bubble Card, or another frontend extension.
- Home Assistant remains responsible for cards, sections, order, visibility, grid placement, and dashboard layout.
- Theme Studio handles visual profiles, supported Home Assistant theme variables, safe previews, import, export, and recovery.
- A control is shown only when Theme Studio can verify that the selected Home Assistant feature supports it.
- Unsupported options are explained instead of being simulated with fragile pixel positioning or private layout overrides.
- Existing legacy CSS is preserved for compatibility, but new everyday workflows must not require users to write CSS, YAML, or Jinja.

## 3. Interaction model

- The preview is navigation and feedback, not a second dashboard editor.
- Tapping a preview region opens the matching visual settings module.
- Changes are previewed safely and applied through the existing Theme Studio profile workflow.
- Desktop may offer more space, but never essential capabilities that are missing on mobile.

## 4. Feature acceptance checklist

A new 0.9 feature is ready only when:

1. It works with standard Home Assistant cards and layout tools without an extra card package.
2. It is fully operable by touch at phone width.
3. It remains keyboard accessible and respects reduced-motion settings.
4. It does not delete or rewrite unknown existing user configuration.
5. It has automated tests for its supported behavior and a clear fallback for unsupported Home Assistant versions.
